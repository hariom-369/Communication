## 2. Valkey loss (`tests/load` scenario `valkey-loss`)

2,000 connected users on 1 API and 2 realtime processes, direct messages at 60/s; Valkey
stopped for 30 s, then started empty.

| | First run (before the fix) | After the fix |
|---|---|---|
| Sends during the outage | 1,740 accepted, 0 errors | 1,740 accepted, 0 errors |
| Send latency p50 / p95 / p99 (whole run) | 9 / 20 / 56 ms | 9 / 26 / 128 ms |
| Sockets during the outage | all stayed open | all stayed open |
| After Valkey returned | nothing happened | every client told to reconnect (spread 15 s), all back within 15 s |
| Deliveries (sender's and peer's socket) | 8,098 live, 0 recovered — **3,902 of 12,000 never delivered** | 7,183 live + 4,817 by catch-up — **0 missing** |

**The defect the first run found:** live delivery runs over Valkey pub/sub, so events published
during the outage were dropped; the messages themselves were stored, but connected clients had
no reason to fetch them and saw nothing until their next reconnect. Fix: when a realtime pod's
subscription comes back after a loss it sends every connection the existing `reconnect` hint
with jitter (as a drain does); clients reconnect and run their catch-up. No protocol or client
change, so it also reaches browsers on an older pinned release. Integration test (mutation-
checked); metric `tessera_realtime_resyncs_total`; production spreads the reconnects over 60 s
(`RESYNC_SPREAD_SECONDS`) so the API is not asked for every socket's ticket at once.

Also corrected in the harness (not the product): its catch-up skipped conversations it had not
seen yet and tracked the highest seq rather than the last contiguous one, so it under-counted
recoveries; it now tracks seqs as the web client does (`processedSeq`, gaps fetched).

Not exercised by this drill (the users were already signed in and connected), but by design and
integration tests (ops/runbooks/valkey-loss.md): while Valkey is down sign-in and sign-up are
refused (their limits fail closed), new connections cannot get tickets, and presence and typing
are unavailable.
